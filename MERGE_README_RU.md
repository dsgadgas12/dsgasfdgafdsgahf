# Объединённый CloudeGift для PAWW / Bothost

Основа — загруженный вами архив `paww (1).zip` (0.6.20). В него перенесена отдельная
демо-лента LIVE из архива CloudeGift LIVE, сохранены заявки на вывод и добавлена
совместимость с переменной порта `PORT` наряду с `SERVER_PORT`.

## Важно: перед загрузкой на Bothost обязательно пересобрать frontend

В текущем архиве сохранена прежняя папка `webapp` как fallback, но её JS/CSS-сборка
старее обновлённого исходника. Поэтому простая загрузка этого ZIP не покажет новые
изменения в интерфейсе.

На компьютере с Node.js 20+ и npm:

Linux/macOS:
```bash
chmod +x build-for-bothost.sh
./build-for-bothost.sh
```

Windows:
```powershell
.\build-for-bothost.ps1
```

Скрипт выполнит `npm ci`, `npm run build` и сформирует новый архив `CloudeGift_Paww_Live_Merge_BotHosting.zip`
с готовым `webapp/`. Загружать в Bothost нужно именно сформированный `*_BotHosting.zip`.

## Что было не так в PAWW

В PAWW исходник `frontend/src/App.tsx` уже содержит пользовательскую историю «Мои заявки»
и админский список «Заявки на вывод», но ранее собранный JS в `webapp/assets` не содержал
строк интерфейса админ-заявок и свежих изменений. Это означает, что исходники и загруженная
Mini App-сборка разошлись. Теперь скрипт сборки проверяет наличие обязательных UI-маркеров
и не позволит молча упаковать старую сборку.

## Запуск в Bothost

- Главный файл: `bot_host.py`
- Python: 3.13 (можно оставить текущую настройку)
- Порт: не задавать вручную; код читает `SERVER_PORT`, а если его нет — `PORT`, затем использует 8000.
- Сохранить существующие секреты и переменные панели; не загружать `.env` с секретами в архив.
- Сохранить существующую постоянную папку базы данных `/app/data` или путь `DATABASE_PATH`, который уже использовался в рабочем PAWW.

После загрузки нового собранного ZIP проверьте `/health`, затем откройте Mini App через Telegram.
