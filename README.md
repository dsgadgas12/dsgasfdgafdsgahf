# CloudeGift 0.6.17 — Telegram Mini App MVP

CloudeGift — MVP Telegram Mini App с каталогом оригинальных Telegram Gifts, кейсами, магазином, профилем, инвентарём, апгрейдером, NFT-слотами, минами, лидербордом, ботом и административным API.

## Что уже находится в проекте

Версия интерфейса: **0.6.17**. Для воспроизведения анимированных TGS-стикеров используется `lottie-web`.

- 119 записей каталога; цены Stars и названия коллекций синхронизированы с `catalog/telegram_gifts_market_stars_2026-11-25.xlsx`.
- 118 оригинальных PNG-моделей из `gifts_unique.zip` скопированы без перерисовки в `frontend/public/assets/gifts/`.
- `Mirage Lamp` оставлен в каталоге без картинки — в исходном архиве модель отсутствовала.
- 10 кейсов с пользовательскими баннерами 4:5; вероятности хранятся в basis points и в каждом кейсе в сумме дают 100%.
- Главное меню с шестью широкими баннерами; для слотов, апгрейда и мин используются прозрачные PNG-иконки пользователя, для кейсов — сундук и две оригинальные NFT-модели.
- На странице кейса вместо крупной статичной NFT-модели показывается бесконечная медленная рулетка с бесшовным повторением; список призов остаётся ниже.
- Логотип в верхней панели заменён на предоставленный объёмный CloudGift wordmark; кнопка «Назад» получила короткую анимацию нажатия.
- Магазин с поиском, фильтром редкости и сортировкой по цене.
- Экран подарка и покупка в локальном демо-режиме.
- Предпросмотр рулетки в кейсе повторяет призы в случайном порядке; при открытии рулетка останавливается на серверном результате.
- Апгрейдер с вращающейся стрелкой и отдельным экраном сгорания подарка.
- Краш с модальным окном ставки, списком игроков текущего раунда и авто-выводом по множителю.
- Верхняя LIVE-лента под логотипом CloudeGift.
- Пополнение: Stars, GRAM (Tonkeeper + memo, пока с ручной проверкой) и NFT-подарком в чат @cloudegift; обычные подарки показаны анимированными TGS-стикерами пользователя.
- Игры: кейсы, апгрейдер, NFT-слоты с серверным RNG, мины. Режим «Краш» скрыт из игрового меню.
- Профиль, инвентарь, промокод, лидерборд: 100 демо-участников с никами из предоставленных Telegram-референсов, локальными Pinterest-style аватарами и превью дорогих NFT-подарков. Состав меняется трижды в неделю, звёзды растут ежедневно в течение двухнедельного сезона.
- FastAPI: проверка Telegram initData, каталог, покупки, открытие кейсов с серверным RNG, апгрейд, Stars invoice, промокоды, общий серверный Crash и Mines, live-лента, продажа подарков и очередь заявок на вывод, admin API.
- Бесплатный кейс: задание на три успешные отправки баннера CloudeCase через Telegram shareMessage, проверка подписки на канал, сохранение прогресса на backend и серверное ограничение одно открытие за 24 часа.
- Aiogram 3 bot: /start, Web App кнопка, Stars pre-checkout и зачисление платежа с защитой от повторного начисления.
- SQLite schema and Docker Compose.

## Важно про режимы

**Для локальной проверки используй `start-local.ps1`:** он запускает backend в DEV_MODE и выдаёт тестовому пользователю 100 000 000 000 демонстрационных Stars один раз. Без backend интерфейс может работать с локальным fallback через localStorage. Демо-баланс не имеет денежной стоимости; реальные платежи, NFT-переводы и выводы не выполняются.

Для настоящего запуска:
1. Настрой `.env`.
2. Укажи настоящий Telegram numeric ID владельца в `ADMIN_TG_IDS` и `VITE_ADMIN_IDS`.
3. Настрой `BOT_TOKEN`, домен и HTTPS.
4. Создай бота через BotFather и установи Mini App URL.
5. Проверь Stars invoice и webhook/polling на тестовом аккаунте.
6. Проведи аудит вероятностей, антифрода, платежей и правил Telegram перед публичным запуском.

## Быстрый запуск на Windows

1. Установи Node.js 20+ и Python 3.11+.
2. Распакуй проект в простую папку, например `C:\CloudeGift`.
3. Открой эту папку в Проводнике, щёлкни адресную строку, введи `powershell` и нажми Enter.
4. Выполни `Set-ExecutionPolicy -Scope Process Bypass`.
5. Запусти `./start-local.ps1`.
6. Дождись установки зависимостей и открой `http://localhost:5173`.

Скрипт создаст локальный `.env` с тестовым пользователем, включит DEV_MODE только для локальной разработки, установит Python- и npm-зависимости и откроет API и frontend в отдельных окнах. После первого запуска открой `frontend/.env.local` и замени `VITE_GRAM_WALLET_ADDRESS` на свой публичный адрес кошелька. В этом режиме доступна демо-админка, но реальные платежи и Telegram-бот не запускаются. Не используй этот `.env` на VPS.

## Локальный запуск — frontend

Требуется Node.js 20+.

```bash
cd frontend
npm install
npm run dev
```

Открой `http://localhost:5173`. Без Telegram WebApp будет работать локальный демо-режим.

## Локальный запуск — backend

Требуется Python 3.11+.

```bash
cp .env.example .env
# Заполни BOT_TOKEN, JWT_SECRET и ADMIN_TG_IDS
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r backend/requirements.txt
cd backend
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

В другом терминале:

```bash
python bot/bot.py
```

Для локального показа административной кнопки без реального Telegram ID можно временно создать `frontend/.env.local` с `VITE_DEMO_ADMIN=true`. Это только визуальный доступ к панели: backend всё равно не разрешит admin API без ID из `ADMIN_TG_IDS`.

Для локальной проверки API: `http://localhost:8000/health`.

## Docker / VPS

1. Установи Docker Engine и Docker Compose plugin.
2. Скопируй `.env.example` в `.env`.
3. Заполни `BOT_TOKEN`, `WEBAPP_URL`, `JWT_SECRET`, `ADMIN_TG_IDS`, `VITE_ADMIN_IDS`, `DOMAIN`, `CORS_ORIGINS`.
4. Направь A-запись домена на VPS.
5. Запусти:

```bash
docker compose up --build -d
docker compose logs -f api bot caddy
```

Caddy получает и обновляет HTTPS-сертификат автоматически. После запуска установи `https://your-domain.example` как URL Mini App в BotFather.

## BotFather

- Создай бота через `@BotFather`.
- Выполни `/setdomain` и укажи домен Mini App.
- Настрой Menu Button / Main App на `https://your-domain.example`.
- В `.env` укажи токен и тот же HTTPS URL.

## Админка

Добавь собственный числовой Telegram ID в `ADMIN_TG_IDS` и `VITE_ADMIN_IDS`. На backend доступ проверяется независимо от frontend. Доступные действия:
- начисление или списание Stars;
- бан / разбан;
- выдача NFT из каталога;
- журнал действий и статистика (API).

Не используй username вместо Telegram ID.

## Оплата

В Mini App для цифрового баланса и игровых цифровых товаров используется Telegram Stars (XTR). Bot создаёт invoice link, а обработчик `successful_payment` зачисляет Stars на баланс. Повторный апдейт не зачислит один платёж дважды — `telegram_payment_charge_id` уникален в таблице `payments`.

Внешний TON Connect / TON-пополнение игрового баланса в этом MVP не подключены. Не отправляй пользователям инструкции для обхода требований Telegram к цифровым товарам.

## Честная игра и безопасность

- Результат открытия кейса в backend определяется `secrets.randbelow`, а не анимацией frontend.
- Вероятности кейсов проверяются на сумму 10 000 basis points.
- Telegram initData проверяется HMAC на backend.
- Admin endpoints требуют JWT пользователя, Telegram ID которого присутствует в `ADMIN_TG_IDS`.
- Все админские изменения, открытия кейсов и покупки записываются в `action_logs` / `transactions`.
- Перед реальным запуском добавь rate limits, мониторинг, резервное копирование, полноценный аудит антифрода, юридические документы, возрастные ограничения и проверку региональных требований.

## Текущие ограничения MVP

- Краш использует общий серверный раунд и атомарный баланс в SQLite; для большой аудитории нужны PostgreSQL, Redis/pub-sub или WebSocket, rate limits и нагрузочные тесты.
- NFT-слоты: каждый спин списывает выбранную ставку (от 25 ⭐); результат определяет backend через `secrets.randbelow`, а при победе случайный подарок из каталога добавляется в инвентарь. Анимация не влияет на результат.
- Апгрейдер: серверный шанс равен 25% от прежней формулы стоимости исходного подарка к целевому, с верхним пределом 23,75%; каждый запуск независим от предыдущих.
- Платные кейсы: дорогой NFT (цена не ниже цены кейса) гарантируется на каждом 20-м открытии каждого кейса для пользователя. В обычных открытиях доступны обычные NFT и возвраты 100 ⭐ (5%) / 300 ⭐ (1,5%).
- Мины используют серверный RNG и серверный баланс, но отдельного общего лобби у режима нет.
- Апгрейдер связан с серверным endpoint и реальными inventory IDs, но перед публичным запуском нужны независимый аудит вероятностей и защита от повторных запросов.
- Лидерборд содержит демонстрационные строки и не является реальным рейтингом.
- Маркетплейс P2P не подключён. Вывод Stars/NFT создаёт заявку с датой и статусом, но фактическую передачу оператор выполняет вручную; автоматического перевода Stars или NFT пока нет.
- Внешняя отправка подарков ведёт на `https://t.me/cloudegift`.
- Это MVP-основа, а не готовая к приёму платежей production-система без настройки секретов и тестирования.


## Обновление интерфейса и общего краша

- После обновления распакуй новую версию поверх старой папки проекта или используй новый каталог.
- Backend создаёт таблицы общего Crash и заявок на вывод автоматически при старте.
- Crash использует общий серверный раунд: 5 секунд на ставки, затем общий коэффициент и серверная фиксация cashout/проигрыша. Интерфейс получает список фактических участников и их статусы через `/api/crash/state`.
- Live-лента показывает только реальные открытия кейсов и cashout в краше/минах из БД. Тестовые пользователи и вымышленные выигрыши в live не добавляются.
- Заявки на вывод Stars/NFT сохраняются в `/api/withdrawals`; пользователь видит дату и статус. Оператор вручную проверяет и выполняет фактическую передачу. Само изменение статуса в админке не переводит Stars или NFT автоматически.
- Продажа подарка в MVP зачисляет на баланс каталожную стоимость из загруженного CSV. Перед публичным запуском проверь бизнес-правила buyback и согласуй их с пользователями.
- Для большой аудитории SQLite + polling недостаточны: переведи хранилище на PostgreSQL, синхронизацию раундов — на Redis/pub-sub или WebSocket, добавь rate limits и нагрузочное тестирование.


### Правила платных кейсов 0.6.17

- Счётчик открытий ведётся отдельно для каждого пользователя и каждого кейса.
- На каждом 20-м открытии выбранного кейса гарантируется NFT, чья каталожная цена не ниже цены самого кейса.
- В остальных открытиях дорогие NFT из этого пула не выпадают; доступны обычные NFT и небольшие возвраты: 100 ⭐ с вероятностью 5% и 300 ⭐ с вероятностью 1,5%.
- `weight_bp` в `frontend/src/data/cases.json` хранит веса внутри обычного и премиального пулов; backend выбирает пул по счётчику, а затем применяет веса внутри него.

В локальном `DEV_MODE` новый тестовый пользователь получает 100 000 000 000 демонстрационных Stars один раз. Эти Stars не имеют денежной стоимости и не являются реальным пополнением.


### Проверка общего краша несколькими локальными пользователями

В локальном DEV_MODE можно открыть приложение в разных браузерных профилях с разными ID:
- `http://localhost:5173/?dev_user=100000001`
- `http://localhost:5173/?dev_user=100000002`
- `http://localhost:5173/?dev_user=100000003`

Каждый ID получает отдельный тестовый аккаунт и баланс. Это только локальная отладка; в production авторизация всегда проверяет Telegram initData.

## GRAM и NFT-пополнение

- В `frontend/.env.local` укажи `VITE_GRAM_WALLET_ADDRESS` — публичный адрес приёма. Не добавляй seed-фразу или приватный ключ.
- Tonkeeper открывается с адресом и уникальным memo. Пользователь вручную выбирает токен GRAM и вводит сумму.
- Для автоматического зачисления требуется подтвердить `VITE_GRAM_JETTON_MASTER_ADDRESS` и подключить серверный индексатор/вебхук транзакций. Пока этот компонент не включён, не обещай автоматическое зачисление GRAM.
- Пополнение NFT открывает чат `https://t.me/cloudegift`; фактическая оценка и зачисление выполняются оператором после проверки подарка.


## Бесплатный кейс и задания (0.6.11)

- Перед первым открытием пользователь отправляет подготовленное сообщение с баннером CloudeCase в три Telegram-чата и подписывается на заданный канал. Отдельного задания «посетить приложение» нет.
- Кнопка «Я выполнил» повторно проверяет количество успешных отправок и членство в канале. После выполнения условия сохраняются для пользователя.
- Telegram подтверждает успешную отправку через `Telegram.WebApp.shareMessage`; отменённая отправка не засчитывается. Telegram не передаёт боту получателя и идентификатор чата, поэтому приложение может подтвердить три успешные отправки, но не может доказать, что это были три разных человека/чата.
- Подписка проверяется через Bot API `getChatMember`. Бот должен быть администратором канала.
- Бесплатный кейс можно открывать один раз в 24 часа. Ограничение проверяется на backend, а не только в интерфейсе. Таймер отображается как `HH:MM:SS.mmm`.
- В `.env` заполни `FREE_CASE_CHANNEL` (`@username` или `-100...`) и `FREE_CASE_CHANNEL_URL` (ссылка на публичный канал или invite-ссылка). Пока эти значения пусты/примерные, проверка подписки не будет успешной.
- Баннер для пересылки доступен по адресу `/assets/share/cloudec-case-invite.jpg`; `WEBAPP_URL` должен указывать на публичный HTTPS-домен приложения.
