# CloudeGift 0.6.18 — подготовка для хостинга с bot_host.py

## Почему возникала ошибка

`bot_host.py` проверяет наличие `webapp/index.html` и `webapp/assets`.
В исходном проекте frontend находится в `frontend/`, а готовой сборки `webapp/` в архиве нет.

## Что сделать на bothost.ru

1. Распакуйте содержимое архива в каталог проекта так, чтобы `prepare-bothost.sh`,
   `frontend/`, `backend/`, `bot/` и `bot_host.py` (файл хостинга) находились
   на одном уровне. Не оставляйте дополнительную вложенную папку `CloudeGift/`.
2. Убедитесь, что в окружении доступны Node.js и npm.
3. В настройках команды запуска укажите:

   ```bash
   bash prepare-bothost.sh && python bot_host.py
   ```

   Если хостинг предоставляет отдельную команду сборки/предзапуска, выполните
   `bash prepare-bothost.sh` в ней, а командой запуска оставьте `python bot_host.py`.

4. Дождитесь сообщения `OK: webapp/index.html и webapp/assets созданы`.
5. Настройте переменные окружения по `.env.example` (как минимум `BOT_TOKEN`,
   `WEBAPP_URL` и длинный случайный `JWT_SECRET`). Не используйте демонстрационные
   секреты в публичном запуске.

## Важно

- Этот архив содержит исходный проект и скрипт сборки. Папка `webapp/` создаётся
  скриптом на сервере из `frontend/dist/`.
- Для скрипта необходим доступ к npm registry при первом `npm ci`.
- Файл `bot_host.py` в исходном ZIP отсутствовал; предполагается, что его
  предоставляет сам хостинг. Скрипт его не заменяет и не изменяет.
- Если bothost.ru разрешает только запуск `python bot_host.py` и не позволяет
  выполнить команду подготовки до старта, попросите поддержку хостинга добавить
  pre-start/build command или выполнить `bash prepare-bothost.sh` один раз
  в терминале проекта.
- Backend API и Telegram-бот должны быть запущены/доступны согласно схеме
  хостинга; наличие `webapp/` устраняет именно проверку отсутствующей сборки,
  но само по себе не настраивает API, домен, HTTPS или Telegram webhook.
